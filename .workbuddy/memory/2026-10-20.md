**F-15（中）**：卖出成交量上限**先取整再比较**，把本可一次成交的零股清仓截断。
- 持仓 1050、委托 1050、volume=10500（原始上限恰好 1050）→ 上限本未绑定，
  取整成 1000 后被判成"绑定"，卖 1000 留 50。
- 持仓 50、volume=800（原始上限 80）→ 取整成 0，直接 blocked:volume。

根因是我把 `cap = int(vol*rate) // lot * lot` 写在比较之前。改法：`_volume_cap`
返回**未取整**的上限，只在"上限真的小于委托"时才按整手缩减。容量真绑定时仍按整手
减仓（1050 清仓、上限 1000 → 卖 1000 留 50）。

**通用的教训**：凡是"上限 + 取整"，先比较再取整，不要先取整再比较。取整本身会
制造一个新的、更小的上限，从而把"没超限"误判成"超限"。

## D 组：公司行动估值（F-01）已修

方案：**只在估值层还原**，成交/整手/T+1/涨跌停全部保留原始口径。
`k_t = adj_close_t / close_t`，持仓市值 = 股数 × 原始价 × `k_t / k_entry`。
`Position.adj_ref` 记录建仓当日 k，加仓按市值加权：`adj_ref' = (old+add)*k / (old*k/adj_ref + add)`。
除权日 k 翻倍抵掉腰斩；分红等价于股息再投资；无公司行动时 k≡1，与旧口径逐位等价。
缺 `adj_close` 时显式告警。

**又抓到一个合成数据缺陷**：原生成器 `close` 取 2 位小数、`adj_close` 取 4 位，
99% 的行不相等 → 等于给每只股票注入 ±0.02% 的假除权噪声（基线漂移 1.5e-5）。
改为 `adj_close = round(close,2) × 累计送转比例`，k 只取 1.0/2.0；并给 000002 加
2022-07-04 的 2:1 送转做端到端验证（送转日权重 4.85% 不变，日收益 -0.24% 与邻日同量级）。

测试 109 → **115 passed**。`adj_close` 必须是**后复权**——前复权会重写历史因子，比值法失真，
这个前提已写进 README 限制清单。

剩余：E 组 F-02（卖单续挂 + 退市清算）、F 组 F-03~F-06。

## 数据源最终结论（2026-10-20 晚）

实测速率（决定架构的关键数据）：
- **baostock 单只 2-6 秒**，且会随机卡死（同一查询一次 2s、一次 >25s）。4941 只 × 2 次
  = 5~8 小时，且 8 分钟连 50 只的第一片都出不来。**放弃作主源**。
  `query_all_stock(day)` 更是 87 秒/天，不可用。
- **gm 批量 100 只约 22 秒** → 4711 只约 17-20 分钟。**改回 gm 作主源**。

gm 的 ST 解法（关键）：`get_history_instruments` 不返回 `is_st`，但
`get_symbols(trade_date=...)` 的**截面**有官方 `is_st`。用月度截面（`calendar[::21]`）
+ `pd.merge_asof(direction='backward')` 向后填充到逐日 → 滞后最多约一个月。
只影响"是否把该股排除出池"；涨跌停用 gm 官方 `upper_limit/lower_limit`，不受影响。

**必须记住的两个反例**（说明不能用 sec_name 判 ST）：
- `600053`：gm 的 sec_name 恒为 `*ST九鼎`（全区间不变，是**静态旧名**），
  但 `is_st=False`，涨跌停 10% → 实际非 ST。
- `600078`：sec_name 是"澄星股份"（不带 ST），但 `is_st=True` → 实际是 ST。
所以 gm 的 `sec_name` 不能用于 ST 判定，必须用截面里的 `is_st`。

验证：600070 全区间 `is_st=True` 且涨跌停比例 5%；600000 为 10%。管道正确。

baostock 侧新增了分片 + 断点续传 + 子进程超时（`_bs_chunk_worker`、`.cache` 目录），
虽然这次没用上，但接口还在，将来若要它补 ST 可以直接跑。

## E 组已修（F-02）

- 引擎维护 `pending_sells` 队列：卖单没成交且标的已不在新目标里 -> 入队，之后
  **每个交易日**（不只信号日）补挂；新信号重新纳入则旧单作废；部分成交按剩余持仓重入队。
- 退市清算：过了 `delist_date` 的持仓按最后收盘价强平，记 `forced:delisted`。
- **踩坑**：`Order.reason` 的语义是"本来就下不出去"，执行层见到非空 reason 直接记
  0 股拒绝单。给补挂单打 `reason="retry:sell"` 当标签，导致补挂全被跳过
  （成交记录连续几天 `sell 0 retry:sell`）。**补挂单的 reason 必须留空**。
- 效果：持仓超 50 只的天数 **63 → 12**（剩余是当日超配、次日卖回的瞬时）；
  累计 +49.96% → +52.03%，Sharpe 0.477 → 0.489。
