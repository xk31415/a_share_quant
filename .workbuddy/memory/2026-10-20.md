**F-15（中）**：卖出成交量上限**先取整再比较**，把本可一次成交的零股清仓截断。
- 持仓 1050、委托 1050、volume=10500（原始上限恰好 1050）→ 上限本未绑定，
  取整成 1000 后被判成"绑定"，卖 1000 留 50。
- 持仓 50、volume=800（原始上限 80）→ 取整成 0，直接 blocked:volume。

根因是我把 `cap = int(vol*rate) // lot * lot` 写在比较之前。改法：`_volume_cap`
返回**未取整**的上限，只在"上限真的小于委托"时才按整手缩减。容量真绑定时仍按整手
减仓（1050 清仓、上限 1000 → 卖 1000 留 50）。

**通用的教训**：凡是"上限 + 取整"，先比较再取整，不要先取整再比较。取整本身会
制造一个新的、更小的上限，从而把"没超限"误判成"超限"。

## D 组：公司行动估值（F-01）已修

方案：**只在估值层还原**，成交/整手/T+1/涨跌停全部保留原始口径。
`k_t = adj_close_t / close_t`，持仓市值 = 股数 × 原始价 × `k_t / k_entry`。
`Position.adj_ref` 记录建仓当日 k，加仓按市值加权：`adj_ref' = (old+add)*k / (old*k/adj_ref + add)`。
除权日 k 翻倍抵掉腰斩；分红等价于股息再投资；无公司行动时 k≡1，与旧口径逐位等价。
缺 `adj_close` 时显式告警。

**又抓到一个合成数据缺陷**：原生成器 `close` 取 2 位小数、`adj_close` 取 4 位，
99% 的行不相等 → 等于给每只股票注入 ±0.02% 的假除权噪声（基线漂移 1.5e-5）。
改为 `adj_close = round(close,2) × 累计送转比例`，k 只取 1.0/2.0；并给 000002 加
2022-07-04 的 2:1 送转做端到端验证（送转日权重 4.85% 不变，日收益 -0.24% 与邻日同量级）。

测试 109 → **115 passed**。`adj_close` 必须是**后复权**——前复权会重写历史因子，比值法失真，
这个前提已写进 README 限制清单。

剩余：E 组 F-02（卖单续挂 + 退市清算）、F 组 F-03~F-06。
