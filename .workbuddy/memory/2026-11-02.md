# 2026-11-02

## 全天没交易：掘金终端拒了老 SDK

一天走了不少弯路，结论记在这里，别再重走。

**现象**：08:30 data 未触发、09:29 trade 报 `1010 无法获取掘金服务器地址列表`
（重试 3 次全挂）、15:35 settle 未触发。一笔委托都没发出。

**被带偏的两次**：
1. `ld_config.ini` 里的 `121.36.148.148:6000` 整机不通（本地测同一 IP 也不通）→ 以为是
   掘金中转服务器下线。但那是无关的旧配置，换到能连的地址后仍然 1010。
2. 重启终端后 netstat 显示已连上 `61.129.116.97:7201` 等，一度以为只是登录态没恢复。

**真因**：`%APPDATA%\Goldminer3\log\gmsdk.*.log` 最后一行——
`[ERROR] GetServices: 2, sdk-version (3.0.191) 不支持，请升级sdk版本`。
终端核心升到 3.9.8(2026-10-22)，老 SDK 在服务发现就被拒。升级到 **3.0.192** 后立刻恢复。
（阿里云源在 144896 字节处稳定截断，换清华源成功；升前整包备份在 `C:\AppData\gm_backup_3.0.191`。）

**当天其实是赚的**：没交易，10-30 买的三只躺着涨，nav 990,495.83 → 1,019,407.83（+2.92%），
其中 000530 涨停（7.92→8.71）。这是运气，同一天跌就是另一份账。

## 新增：失败推送要说明白

`live_auto.failure_hint()`——失败时从当天日志尾部抓 gm 错误码 + 失败步骤，输出「为什么」和
「有没有下单」两句话，gm 掉线时推送标题直接写「⚠️ trade 中止：掘金终端不可用」。
关键判断：卡在 pull-holdings / live_signal = **一笔委托都没发出去**；卡在 place-orders =
**可能有部分委托已发出**，必须人工核对。测试 417 → 421。

## 环境坑：SSH 会被限流

一晚开了 40+ 次 ssh（paramiko 和 ssh.exe 交替），认证阶段被 `Connection reset`，连
TCP 22 都通也连不上。规律是封十几分钟后恢复。**做法：一条 paramiko 连接做多件事**
（上传 + 跑命令），不要每条命令开一次新连接。更进一步写了个常驻会话
（`_dstest/ssh_daemon.py`，本地 19555 端口复用一条连接 + sftp 上传），已有连接不受新连接限流影响。

## 补的几刀

* `failure_hint()`：失败推送写明「为什么」（gm 错误码翻译）+「有没有下单」。
  卡在 pull-holdings / live_signal / update_dataset = **一笔委托都没发出去**；
  卡在 place-orders = **可能有部分委托已发出**，必须人工核对。
* `data_freshness()` + trade 前自愈：数据落后于交易日历就先跑 data 段，补失败就
  **拒绝交易**（不用旧数据下单）。今天 08:30 没跑、数据停在 10-29，trade 却照常启动——
  若不是 gm 也挂了，它会拿两天前的数据算信号。
* `patrol()`：trade / settle 开头跑 `scripts/watchdog.py`，把「前一段没跑」喊出来。
  **oncall 死区**：脚本没启动就没有任何消息，只能靠下一个 stage 或外部看门狗。
* `live/equity_history.csv` 补了 `2026-10-30, 990495.83`（今天 09:29 挂在第一步没写进去）。
  不补的话次日「较上日」会把 +2.92% 算成 -1.11%，方向反。

## 两件没做成的

* **计划任务加 StartWhenAvailable 失败**：`Set-ScheduledTask` 报
  `0x80070775 使用账户的当前密码未知`。`LogonType=Password` 的任务改任何设置都要重输密码，
  只能人工在远程桌面做。
* **NightWatch 的心跳监控等于没开**：配置里 `StaleMinutes=1080`（18 小时）+ 计划窗口
  08:30-16:00 + `Mode=Off`（窗口外不检查），窗口内永远攒不到 18 小时。而项目自带的
  `scripts/watchdog.py` **从来没有计划任务在跑它**——今天三条故障它都能报，只是没人叫它。
