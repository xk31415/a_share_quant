### GitHub 推送被墙的解法（下次直接用）
`github.com` DNS 被污染成 28.0.0.8 / 2001:2::8（8.8.8.8 也一样），22 与 443 全不通
（TCP 能连、SSH 握手被切）。本机 `127.0.0.1:7897` 是 Clash 混合端口：
- **HTTP 代理模式到 GitHub 是 000，socks5h 才通**（`curl -x socks5h://127.0.0.1:7897` 200）。
- 节点不放行 22 端口，只通 `ssh.github.com:443`（GitHub 官方备用端口）。
- 做法：`C:/Users/67478/AppData/Local/Temp/socks5_ssh.py`（SOCKS5→stdio 隧道，
  给 `ssh -o ProxyCommand` 用），命令：
  ```
  export GIT_SSH_COMMAND="ssh -o ProxyCommand=<py> <脚本> %h %p"
  git -c "url.ssh://git@ssh.github.com:443/xk31415/a_share_quant.git.insteadOf=git@github.com:xk31415/a_share_quant.git" push origin main
  ```
**踩坑**：写隧道脚本时 socket 只有 `sendall` 没有 `write`、BufferedReader 只有 `read1`
没有 `recv`——混用会抛异常被 except 吞掉，表现是"连接建立后立刻 close"（ssh 报
`Connection closed by UNKNOWN port 65535`），极难定位。stdio 与 socket 必须各写一个适配函数。

  阈值设小了天天误报、设大了（18 小时）就只能抓"整天一次没跑"，
  抓不到"某个 stage 单独挂"
- **Schedule 只认星期，不认节假日**：国庆/春节（周一到周五）会误报

结论：NightWatch 兜"整天全没跑"（正是 10-26/27 计划任务路径错那种），
