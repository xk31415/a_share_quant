## 07:30 纠正：上一条给的 `net accounts /lockoutthreshold:50` 跑不通

- 只读跑 `net help accounts`：这台机器语法**只有**
  `/FORCELOGOFF /MINPWLEN /MAXPWAGE /MINPWAGE /UNIQUEPW /DOMAIN`，
  **没有**任何锁定阈值参数。上一条建议作废，别让主人白跑一趟。
  （`net accounts /lockoutthreshold` 是网上常见写法，本机不支持。）
- `net accounts` 当前值（中文系统 cp936 解码）：锁定阈值 10 / 锁定持续时间 10 分 /
  锁定观测窗口 10 分 / 计算机角色 SERVER / 工作组。
- 正确途径是**本地安全策略**：只读 `secedit /export /areas SECURITYPOLICY` 拿到
  UTF-16LE 的 inf，`[System Access]` 段里字段名与当前值：
  `LockoutBadCount = 10`、`ResetLockoutCount = 10`、`LockoutDuration = 10`、
  `AllowAdministratorLockout = 1`（所以内置 Administrator 也会被锁）、
  `PasswordComplexity = 1`（密码复杂度开着，爆破没得手的一个原因）。
- 可用做法：① `secpol.msc` → 账户策略 → 账户锁定策略 → 阈值 10→50，另两项保持 10/10；
  ② `secedit /export` 导出完整 cfg → 只把 `LockoutBadCount` 改成 50 → `secedit /validate`
  → `secedit /configure /db <临时sdb> /cfg <inf> /quiet` → `net accounts` 核对 50/10/10。
  备份 inf 即可回滚。**必须「导出完整 inf 只改一行」**，别自建三行 inf（会把密码策略等
  重置成默认）。`secedit /?` 这台只给总语法、不列子命令参数，故 configure 不带 `/areas`。
- 另一个旋钮 `AllowAdministratorLockout = 0` 能让内置管理员永不锁，但等于让爆破无限试
  密码，**不建议**；提高阈值更稳妥。
- 以上全是只读核查，**没有执行任何策略改动**，临时 inf 已在脚本内删除；探针已清。
