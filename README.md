# A 股量化策略研究与回测框架

一个**研究基础设施优先**的 A 股量化项目：从数据构建、因子研究、回测到实盘信号与成交对账，
全流程可跑。目标不是找"最赚钱的策略"，而是搞清楚"赚的是不是真的"。

> - 接手先读 [`HANDOVER.md`](HANDOVER.md)（交付状态、上线清单、约定）；AI 接手再读 [`AGENTS.md`](AGENTS.md)。
> - 操作手册（回测、数据、实盘每日流程、对账）见 [`QUICKSTART.md`](QUICKSTART.md)。
> - 研究结论与实盘判定见 [`reports/research.md`](reports/research.md)；防未来函数审计见
>   [`reports/lookahead_audit.md`](reports/lookahead_audit.md)。
>
> **回测结果不代表未来收益。本项目用于研究，不构成投资建议。**

## 4. 数据

### 4.1 为什么不入库

三份数据集合计 366 MB、`bars.parquet` 单文件最大 166 MB：超过 GitHub 单文件 100 MB 硬限制；
`update_dataset.py` 每天整体重写 parquet，进历史就删不掉；行情授权跟账号走，不能转分发。

替代方案是入库**内容指纹**：行按主键排序、浮点按原始位模式、NaN 先抹平后取哈希，
换 pandas/pyarrow 版本仍判一致；真实差异（少几天、改一位小数、换列类型）会报出来并指名差异列。

```bash
python scripts/build_dataset.py --source gm --start 2020-01-01 --end 2024-12-31 \
    --benchmark 000852 --out data/processed --verify-manifest
python scripts/data_manifest.py verify      # 三份一起校验，不一致退出码 1
python scripts/data_manifest.py show        # 指纹摘要，不读数据
```

`processed_2025_2026` 每日增量更新，它的指纹会随数据增长而变；`update_dataset.py` 不自动改写指纹
（指纹的用途是钉住某一版数据）。

没有 token 也能跑通整条链路：`python scripts/generate_synthetic_data.py` 生成合成数据，
或 `--source baostock` 免费拉真实数据。

### 4.2 数据源与构建

`scripts/build_dataset.py --source baostock|gm|qmt` 产出四张表（bars / instruments / status / calendar）
加可选 `benchmark.csv`，并执行六条硬校验，任一不过直接报错、不产出数据集：

1. `symbol` 是 6 位字符串（前导零不能丢）；
2. `instruments` 里必须有已退市证券；
3. 涨跌停价逐行覆盖（`limit_exempt` 之外不许为空）；
4. 复权因子 `k = adj_close/close` 单调不减（下降基本等于拿到了前复权）；
5. 每个交易日的证券数不能异常瘦；
6. 停牌标记与成交量自洽。

| 源 | 逐日 ST | 涨跌停价 | 退市股 | 说明 |
|---|---|---|---|---|
| `baostock` | 官方 `isST` | 规则表推算 | 1197 只 | 免费、无需 token |
| `gm`（三份现有数据集） | `get_symbols(trade_date)` 月度截面 | 官方值 | 截面并集还原 | 需 `GM_TOKEN` 与装了 gm 的 Python |
| `qmt` | 无 | 无 | 待测 | 只能降级 |

涨跌停规则表（`builders.limit_ratio`）：主板 10%、主板 ST 5%（2026-07-06 起 10%）、
创业板 2020-08-24 后 20%、注册制新股上市前 5 日无涨跌幅；与 gm 官方值实测完全一致。

### 4.3 还缺的数据

| 数据 | 用途 | 现状 |
|---|---|---|
| 日线（含退市股、后复权、涨跌停价）、上市退市日期、交易日历、基准指数 | 信号、成交、股票池、绩效 | ✅ |
| 逐日 ST / 停牌 | 股票池与成交约束 | ⚠️ ST 用月度截面，最多滞后约 20 个交易日 |

| 估值（PE / PB / 市值）、股息率 | 估值因子、市值中性化、区分低波与红利 | ❌ |
| 指数成分变更历史 | 成分股池 | ❌ |
| 逐日行业快照 | 行业归因、行业中性选股、热点+龙头 | ❌ 只有当前静态分类 |

## 5. 配置

- `config/settings.yaml`：回测区间、基准、初始资金、佣金（0.025%，最低 5 元）、印花税（卖出 0.05%）、
  滑点（0.05%）、调仓频率（月度）、最大持仓数（50）、单票上限（10%）、建仓现金缓冲（1%）、
  涨跌停/停牌开关、整手 100 股、成交量上限（0.10）；
- `config/universe.yaml`：上市满 60 个交易日、剔除 ST/停牌/退市、**板块白名单**（默认只留沪深主板
  与创业板，排除科创板、北交所、B 股）、`excluded_symbols`、流动性下限。市值/行业/指数成分过滤
  是预留项，启用即报错；
- 数据目录由命令行 `--data-dir` 指定；代码不读环境变量（gm 拉数据时读 `GM_TOKEN`）。

**交易规则与数据源一律走配置，不硬编码进策略。**

## 6. 回测

```bash
python scripts/run_baseline_backtest.py --data-dir data/processed_2025_2026 \
    --start 2025-01-01 --end 2026-10-20 --benchmark 000852
# 期望 annualized_return = 0.0610828468971103
```

常用参数：`--strategy equal_weight|momentum|low_vol|hype_watch|hotspot`、`--window/--skip/--reverse`（动量与反转）、
`--industry-neutral`、`--liquidity`、`--capital`、`--capacity-aum`、`--freq D|W|M`、`--seed`。
热点+龙头另有 `--top-k/--top-m/--min-industry-members`，**日频按需调仓**（不沿用上面的月频），
规则见 [`reports/hotspot_dragonhead.md`](reports/hotspot_dragonhead.md)。
这是研究规则，没有回测数字，不接入实盘。

产物写入 `results/EXP-<id>/`，元数据（数据指纹、规则、参数、Git commit）写入 `experiments/EXP-<id>.json`：

| 文件 | 内容 |
|---|---|
| `equity_curve.csv` / `.png` | 净值与回撤 |
| `positions.csv` | 每日持仓快照 |
| `trades.csv` | 逐笔成交，含被拦截记录（`blocked:*`）与退市强平（`forced:delisted`） |
| `turnover.csv` / `costs.csv` | 单边换手与成本，索引是**成交日**（t+1） |
| `annual_returns.csv` / `monthly_returns.csv` | 收益分解 |
| `metrics.json` | 全量指标、成本归因、行业暴露、暖机与基准配对计数 |

判断一次回测是否可信：`trades.csv` 的 `note` 分布里真的出现了 `blocked:limit_up/limit_down/suspended`
才说明对应约束被触发过；控制台的 `[warn]`（尤其 survivorship / warmup / status）必须看。

## 7. 数据模型

| 用途 | 价格 | 说明 |
|---|---|---|
| 因子 / 信号 | `adj_close`（后复权） | 避免除权假跳空 |
| 成交模拟 | `open/high/low/close`（原始） | 真实可成交价 |
| 涨跌停约束 | `limit_up/limit_down/pre_close`（原始） | 交易所规则基于原始价 |
| 持仓估值与卖出结算 | 原始价 × `k_t/k_entry` | `k = adj_close/close`，抵消除权跳空，两处同口径 |
| 财务数据 | 必须带 `announce_date` | t 日信号只能用公告日 ≤ t 的行 |

- **停牌/ST 的权威来源是 `status` 表**：引擎启动时把它合并进 bars；`bars` 天然只含有行情的行，
  它的 `is_suspended` 不能用来判断停牌；
- **涨跌停必须由数据提供**：开关打开时缺列或任意一行为空，引擎启动即报错；确实没有涨跌幅的日子
  用 `limit_exempt: true` 显式标注；
- **停牌日的行情不参与估值**，数据商给的理论价 bar 会让净值凭空跳变；
- **基准从 `benchmark.csv` 读**，不在 `bars` 里按代码匹配（指数与个股代码会撞车）。

## 8. 防未来函数机制

- **交易权限**：引擎把策略目标与当日股票池求交，池外代码不下单并写入 `universe_violations.csv`；
- **数据校验**：`BacktestEngine.run()` 自己执行 `validate_dataset`，编程式调用同样会被校验；
- **时间对齐**：t 日收盘出信号、t+1 开盘成交；策略只拿到 `trade_date ≤ as_of` 的行情；
- **股票池**：`get_universe(as_of)` 只用当时已知的上市天数、退市日期、状态；
- **财务数据**：`latest_known(..., date_col="announce_date")`；
- **幸存者偏差哨兵**：全表无退市股、或行情中途消失却未标退市时告警；
- **行业归因**：优先逐日快照，退回静态分类时显式告警。

逐项机制、锁定测试与真实数据审计结果见 `reports/lookahead_audit.md`。

## 10. 研究结论（摘要）

| 策略 | 2020-2024 | 2015-2019 | 2025-2026 |
|---|---|---|---|
| 中证1000 | +1.07% | -12.48% | +9.56% |
| 宇宙等权（及格线，5 月起窗口） | +9.85% | -6.61% | +17.09% |
| 等权 50 只 | +11.15% | -10.33% | +6.11% |
| 低波·行业中性 | +14.29% | -5.14% | +5.74% |
| 12-1 动量 | -11.34% | -4.25% | 样本不足 |
| 60 日反转 | +7.34% | -3.79% | +17.40% |

没有策略有稳定超额；低波的低回撤基本来自低 beta；反转只在高流动档内有选股效应、换手 9 倍；
择时规则三段都不成立。完整数字、门槛与判定见 `reports/research.md`。

## 11. 实盘链路

`live_signal.py` 不做选股，只把"冻结样本 + 目标仓位"翻译成委托单：季度调仓（1/4/7/10 月）、
整手买卖、清仓才带零股、停牌与已持有跌停股冻结、数据过期拒绝出单、资金不足拒绝出单。
`config/live.yaml` 的 `strategy: hype_watch` 改走 `live_signal_hype.py`（观察池仿真，不是研究结论）。
`reconcile.py` 核对成交与委托、计算滑点与持仓偏离、生成下次要读的持仓表，并防止同一批成交重复入账。

## 12. 已知限制

编号用于代码注释与文档互相引用；新增一律追加在末尾。

**数据**

1. **缺财务、估值、指数成分历史数据**。Value/Quality 因子、市值中性化、成分股池都做不了；
   相关过滤项启用即报错，不静默忽略。
2. **复权口径的前提是后复权**。估值与卖出结算都用 `原始价 × k_t/k_entry`，若 `adj_close` 是前复权
   （每次除权重写历史），比值法失真；缺 `adj_close` 时引擎告警。除权用"股数不变、按复权价结算"表达：
   ① 整手约束按虚拟股数算（真实世界送转后股数变多）；② `cost` 按原始成交额计，与复权成交额差
   `(1-k/ref) × 费率` 的二阶小量。
3. **ST 状态最多滞后约 20 个交易日，且不能用证券简称补判**。gm 的 `is_st` 来自 `get_symbols(trade_date)`
   月度截面（向后填充，无未来函数）。gm 返回的 `sec_name` 是**当前**简称：`002168` 简称一直是"ST惠程"，
   但 2024-10 之前官方涨跌幅都是 10%。用简称判 ST 等于用未来的戴帽状态剔除历史股票。
   2020-2024 现有 `is_st` 与官方 5% 涨跌幅一致率 98.83%。
4. **退市整理期没有时点信号**。原 `*ST` 股进入最后约 15 个交易日的整理期后，gm 截面 `is_st` 翻回 False，
   重新混入股票池（三份数据集 7 / 15 / 9 只）；整理期首日无涨跌幅、源表仍给 ±10% 跌停价
   （`assemble` 默认告警，`--exempt-limit-breach` 才豁免）。2025-2026 的 60 日反转
   （`EXP-20261022-151421-2220`）因此买入 `300029`、`002808`、`002898`，全表成交净 +16,031 元、
   约 +1.3pp 年化；"剔除后约 16.5%"是粗估，**存疑**。gm 的 `delisting_begin_date` 为空，
   要修需要另找数据源（交易所退市整理期公告）。
5. **行业分类是当前静态分类**。归因时显式告警；`--industry-neutral` 选股同样读它，
   存在微弱前视（证监会大类年变更率约 1%）。
6. **2015-2019 数据集里有 2 只孤儿代码**。`000022`、`000043` 因复权因子被源重置只从 `bars` 剔除，
   仍在 `instruments/status`，股票池会返回它们；构建器已改为三表同步剔除，但现有数据集未重建。
   17 组实验均未抽中；全池脚本按股票池索引 `bars` 会 `KeyError`。
7. **`symbol` 没有交易所后缀**。`000001` 既是平安银行也是上证指数，`000905`、`000852` 与个股撞码。
   板块白名单靠前缀，同码只能靠 `excluded_symbols` 兜底；基准必须从 `benchmark.csv` 读，
   按代码在 `bars` 里匹配会读到个股价格且不报错。
8. **基准是价格指数**（不含分红），组合端估值含分红，口径差约 1~1.5%/年会算进超额。

**回测引擎**

9. **停牌持仓按最后已知价冻结估值；退市日按最后已知价强平**（`forced:delisted`）。
   不建模退市整理期与清算价，真实整理期价格通常更低，终值偏乐观。
10. **受阻的卖单逐日重挂，但期间持仓数可能超过 `max_positions`**。跌停/停牌拦下的卖单进入
    `pending_sells` 次日继续挂，新信号重新纳入目标时撤销。
11. **开盘即涨停视为买不进**，不建模盘中部分成交。
12. **引擎全量预载行情到内存**，超大股票池需要改分块。
13. **因子内部的自造未来**（`shift(-1)`、跨时间标准化）框架无法静态阻止，只能靠篡改测试。
14. **换手是单边口径** `(买入额+卖出额)/2/权益`。
15. **停牌/退市持仓的市值不计入定仓基数**（否则同一笔钱被重复分配），但计入总权益，
    所以持仓权重合计会低于 100%。
16. **印花税用单一税率 0.05%**，未按成交日切换（2023-08-28 前为 0.1%）；过户费未建模。
17. **成交量上限用成交日全日成交量**，是事后容量代理；实测开盘量只有全日的 1/5~1/2。
    容量上限约 1 亿量级（`reports/research.md` §9）。库默认关闭，基线脚本从配置读 0.10。
18. **绩效从首次持仓日的前一个净值点开始算**。建仓前的空仓期（约 78 个交易日）不计入年化/波动/夏普/超额，
    但保留在 `equity_curve` 与 `cumulative_return`；`metrics.json` 的 `warmup_days`、`n_cash_only_days`、
    `first_active_date` 分别记录。截断**不区分"股票池为空"与"策略主动空仓"**：后者截掉会让超额偏乐观
    （实测前 10 天主动空仓、基准 +2%/日时，年化超额 -3.71pp 变成 -2.52pp）。现有回测的空仓期全部来自
    股票池预热，不受影响；**写择时策略之前必须先让指标层知道股票池哪天有可交易标的**。
19. **暖机截断的两条路径可能分叉**。`trim_warmup` 优先用持仓表，拿不到才退回"净值开头连续平盘"；
    零成本且成交日收盘净值仍等于初始资金时，两条路径给出不同切点。默认成本模型下不触发。
20. **没有持仓表时 `first_active_date` 报的是净值仍等于初始资金的那天**（首个收益的基准点），
    `n_cash_only_days` 相应少算。引擎正常产出持仓表时不走这个分支。
21. **`results/` 里有 5 组实验的拦截计数比现行代码多**。引擎曾在调仓日对同一只票重复挂卖单
    （第二张记成 0 股拦截），且未成交卖单按 `set` 顺序重挂导致结果随 `PYTHONHASHSEED` 在第 15 位有效数字上变化，
    两处均已修。重跑 18 组：收益类指标全部不变，`150448`、`150718`、`150940`、`151206`、`192736`
    的 `n_blocked_trades` / `n_trade_events` 分别少 2 / 4 / 1 / 3 / 5 行；`results/` 中的产物是修复前的。

**研究口径**

22. **等权基准是一次散列抽样的 50 只**，收益几乎全部来自等权这个权重方案本身。
    判断等权策略要先比宇宙等权（`reports/research.md` §2），并标明调仓频率与窗口：
    日频等权含再平衡红利，不能当及格线；算对齐窗口的参照值时**不能先切片 `bars` 再做暖机**，
    否则已建仓的月份会被当成第二次暖机删掉。
23. **没有任何策略通过实盘门槛**；滑点、成交率、成本都是配置值不是实测值，只有 paper trading 能回答。
24. **长回看窗口的策略在短数据段上不可比**。12-1 动量在 2025-2026 段暖机吃掉 64%，算出的 +25.46pp
    超额是窗口选择的产物。评策略先看 `effective_days / trading_days`，低于约 70% 不与其他段并列。
25. **高换手策略的超额押在滑点假设上**。60 日反转年换手 9.04 倍，滑点每增加 0.25% 年化少约 2.26pp。

**实盘**

26. **执行日闸门用"现价"近似开盘价**（`gm_bridge.apply_execution_gate`）：09:15 下单时开盘价
    还没出来，用现价（盘前 = 集合竞价参考价）对当日官方涨跌停价判定，与回测 `execution.py`
    同口径（涨停不买、跌停不卖、不看是否持有）。一字板的竞价参考价就是板价，判得出来；
    竞价参考价与最终开盘价不一致的罕见情形会与回测分歧。三处已知残留：
    ① 信号层 `live_signal.py::_compute_tradeability` 仍用 t 日收盘冻结**已持有**的跌停股——
    这是"别把卖不掉的持仓当已回笼现金"的规划近似，方向保守（多持一天）；
    ② 无涨跌停价（如无涨跌幅限制的新股）在实盘被 `blocked:no_limit_data` 拦下，
    回测 `limit_exempt` 则放行；
    ③ **`current()` 盘前返回的是昨收还是竞价参考价，尚未在真实盘前验证**。收盘后验证能正确
    拦下封板股（`price` 就是收盘价）；若盘前返回昨收，它既非空也不等于涨停价，闸门判不出
    封板会直接放行——而 `live_signal_hype` 的信号层过滤已移除，此时只剩这一道防线。
    上线前须在 09:15 前后 dump 一次 `current()` 的 `price` / `open` 核对。
27. **非季度月"只检查"即使有告警，退出码仍是 0**（资金不足拒单除外）。依赖退出码的调度要另外解析输出。
28. **重复入账指纹只防"同一批成交被再对一次"**。改单、分红送股、漏对一笔、回报延迟都防不住，
    **每周至少一次用券商持仓导出逐只核对股数**。
29. **实盘有资金下限**。一手超过 2 倍单只预算的票不买，单只预算低于最小下单额（2,000 元）的空仓票也买不进；
    这类票超过目标数的 `--max-unfunded`（默认 10%）时拒绝写委托，并给出买齐所需总资产。
    2026-10-20 冻结样本、100 只、40% 仓位：总资产 80 万通过（1 只买不进），60 万被拒（28 只）。
    "全部买齐所需总资产"由最贵的一只决定（当前约 201 万），会明显高于实际可用的门槛。
30. **炒作苗头观察池（`hype_watch`）没有已验证收益，不是买卖建议。**
    策略类 `paper_only` 必须为 true，回测只产纸面记录。仿真账户的下单不走
    `live_signal.py`（那条仍是等权冻结样本），而走 `scripts/live_signal_hype.py`：
    `live_auto.py` 在 `config/live.yaml` 的 `strategy: hype_watch` 时调用它。
    这条仿真不改变 `reports/research.md` 的判定。超额基准是中证1000（`000852`），
    因为 `benchmark.csv` 里只有这一条。股票池与回测相同：`universe.yaml` 的板块白名单
    （不含科创板、北交所）、上市满 60 个交易日、剔除 ST / 停牌 / 退市，并始终排除指数代码
    `000300`。`000852` 同时是石化机械，不因为它当基准就被剔出股票池。数据距今超过 15 天拒绝出单。
    `--dry-run` 不写委托，也不改 `live/equity_history.csv`。没传 `--position` 时用
    `live.yaml` 的 `position`，不默认满仓。纯规则回测要有 `themes.csv`（`start_date` 必填，
    缺了直接报错，不会把当前成分回填到历史）；只有 `bars` 上的当日 `theme` / `industry`
    列时才退回行情里的标签，用 `industry` 会告警，静态分类与限制第 5 条一样有前视。
    仿真在不传 `--themes` 时，只用数据最后一个交易日的 `instruments.industry` 当题材代理，
    更早的 `--as-of` 直接拒绝。观察窗口 T+1/T+3/T+5 的收盘收益是事后指标，信号日不可知，
    不参与目标权重。断路器在回测里用引擎权益；仿真里用出信号时的账户估值
    （现金 + 持仓市值），不是成交回报之后的净值。回撤是近 20 个交易日的滚动峰值，
    不是从回测起点起的历史高点；冷静期按信号日计数。次日成交价若已封板，按执行日闸门买不进。
    单边约 0.1% 是配置里的佣金率+滑点率，不是实测滑点，小单还受 5 元最低佣金影响，卖出另计印花税。
31. **`placement.csv` 在逐笔发送之前就写盘**。整体失败（gm 会话没起来、下单接口报错）时文件
    已经存在，`reconcile` 会把这些委托当"已发送未成交"处理。方向是报出差异、不会静默丢单，
    但**别用 `placement.csv` 的存在推断"单子确实发出去了"**。
32. **测试用的假 gm 包写在 `live/_tmp/gm`**（`_run_in_context` 的子进程 `sys.path[0]` 就是
    脚本所在目录，会优先命中它）。测试被中断时该目录会残留，之后所有 `gm_bridge` 调用都
    import 到假包——表现是"下单成功但账户里没有真单"。跑完测试或部署前确认它不存在：

**研究规则**

33. **热点+龙头在没有逐日行业快照时不能产出研究结论**。规则见 `reports/hotspot_dragonhead.md`。

    两处都没有时返回空组合并告警，不用全市场动量顶上。空仓是缺数据。

**实盘：演练的隔离是逐条列的**

34. **演练（`live_auto --dry-run`）的每一条写盘路径都必须显式隔离到 `live/_dryrun/`**。
    现在隔离了六处：orders、signal_log、summary、持仓、现金、心跳。但这是**逐个指定**的，
    不是白名单机制——以后新增任何写盘路径，都要自己记得隔离。
    2026-10-28 踩过：只隔离 orders 时，`pull-holdings` 把演练持仓写进生产
    `live/holdings.csv`，15:35 的 reconcile 把它当「期初持仓」再加一遍当日成交，
    000678 从 10400 变成 **20800（翻倍）**。同一天还漏了现金路径，演练会读到生产现金。
    判断标准：**演练只该回答「会出什么单」，不该改动任何账户账本。**

**实盘：下单定价**

35. **挂单价用执行日 09:30 的实时价 ×(1±滑点)，不是信号日收盘价**。计划任务 09:15
    启动（拉持仓、算信号），`stage_trade` 等到 `config/live.yaml` 的 `order_time`
    （`09:30:05`）才调 `place-orders`——09:15 只是集合竞价的**申报**窗口，09:20-09:25
    不可撤单、09:25 才撮合出开盘价、09:30 才连续竞价，在 09:15 下单没有任何真实价格。
    定价在 `gm_bridge.apply_execution_pricing`：买入 = 实时价 ×(1+slippage) 向上取整到分、
    卖出 = ×(1-slippage) 向下取整到分，两者都夹在当日涨跌停价内；现金不足时按**比例**
    缩减全部买单（整手向下取整），与 `ExecutionSimulator` 同口径。
    `orders.csv` 保留信号日意图价，`placement.csv` 记实际挂单价，两者之差就是当天的价格漂移。
    2026-10-28 之前挂的是信号日收盘价，实测三笔全错、方向还不一致：000678 委托 16.01
    而当日最低 16.66（真实整天买不到，仿真凭空 +10%）、601086 委托 12.62 而开盘 12.26
    （多付 3%）、001318 委托 13.31 而开盘 13.54（真实要等盘中跌破才成交）。

## 13. 纪律

- 不自动寻找"最赚钱策略"、不暴力调参、不按最高收益挑参数；
- 不使用未来数据、未来股票池、未来财务数据；
- 不为提高收益修改交易规则，不为"跑通"放宽校验；
- 不删除或隐藏失败的回测，不把回测结果包装成投资结论。
