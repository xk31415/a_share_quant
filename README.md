# A 股量化策略研究与回测框架

一个**研究基础设施优先**的 A 股量化研究项目。目标不是立即寻找"最赚钱的策略"，
而是建立严谨、可重复、可扩展、尽可能避免未来函数与数据泄露的研究框架。

> **回测结果不代表未来收益。**
> **本项目用于研究，不构成投资建议。**
>
> 三份真实数据集（2020-2024 / 2015-2019 / 2025-01~2026-10）**不入库**，
> 仓库里只存它们的指纹 `data/MANIFEST.json`。别人拉下项目后按第 2.1 节
> 重建并校验指纹，就能确认拿到的是不是同一份数据。

---

## 1. 项目用途

> **想直接上手操作，请看 [`QUICKSTART.md`](QUICKSTART.md)**（含本机已验证的命令与常见问题排查）。

- 建立可长期沉淀的 A 股因子/策略研究流水线；
- 以机制（而非自觉）防止未来函数、幸存者偏差与数据泄露；
- 用统一的实验记录保证每一次回测可复现。

### 2.1 数据为什么不入库

三份真实数据集合计 **366 MB**，`bars.parquet` 单文件最大 **166 MB**。不入库有三个理由，
前两个是工程上的，第三个不是：

1. **GitHub 单文件硬限制 100 MB**，`git push` 会直接拒绝；转 LFS 后又受免费额度限制
   （1 GB 存储 / 1 GB 月流量，别人 clone 三次就耗完）；
2. **数据每天在长**。`update_dataset.py` 补数据时 parquet 是整体重写，每次提交都是一个
   新的 66 MB blob，一旦进历史就再也删不掉，几周就能把仓库推到 GB 级；
3. **数据授权跟账号走**。行情来自掘金 / baostock 的 token，公开转分发通常不在授权范围内。

替代方案是入库**内容指纹**（`data/MANIFEST.json`，17 KB）：行按主键排序、浮点按原始位
模式、NaN 先抹平后取哈希，所以换 pyarrow/pandas 版本、文件字节变了仍判一致；真正的数据
差异（少几天、复权因子变了、某列类型变了）会立刻报出来，并指出是哪几列。

```bash
# 别人拉下项目后：重建 → 校验
python scripts/build_dataset.py --source gm --start 2020-01-01 --end 2024-12-31 \
    --benchmark 000852 --out data/processed --verify-manifest
python scripts/data_manifest.py verify      # 三份一起校验，不一致时退出码 1
python scripts/data_manifest.py show        # 指纹摘要，不读数据，秒出
```

这比"发一份数据给我"更强：它验证的是**"你重建出来的和我回测用的逐字段相同"**，
而不只是"我拿到了某个文件"。注意 `processed_2025_2026` 是每日增量更新的窗口，
它的指纹会随数据增长而变，校验前先确认更新到哪一天。

暂时拿不到 token 也能把整条链路跑通：`python scripts/generate_synthetic_data.py`
生成合成数据（30 只 × 780 交易日，seed=42 可复现），或 `--source baostock` 免费拉真数据。

## 4. 如何配置

- `config/settings.yaml`：回测区间、基准（默认沪深300）、初始资金、
  佣金（双边 0.025%、最低 5 元）、印花税（卖出 0.05%）、滑点（0.05%）、
  调仓频率（默认月度）、最大持仓数（20）、单票上限（10%）、
  建仓现金缓冲（1%，覆盖费用与滑点）、涨跌停/停牌开关、整手 100 股。
- `config/universe.yaml`：股票池规则——上市满 60 个交易日、剔除 ST/停牌/退市、
  **板块白名单 `allowed_prefixes`**（默认只留沪深主板 600/601/603/605/000/001/002/003
  与创业板 300/301，排除科创板 688/689、北交所 43x/83x/87x/92x、B 股 200/900）、
  `excluded_symbols`（如基准指数代码）。
  指数成分、市值、行业过滤为预留项（启用即报错）；流动性下限已实现。
  **ST 过滤只在这里配置**（`settings.yaml` 不再有重复开关）。
- 数据目录由命令行 `--data-dir` 指定（默认 `data/interim/synthetic`）；
  当前代码**不读取任何环境变量**，`.env.example` 仅为将来接入数据源 API 预留。

**交易规则与数据源一律在配置中，禁止硬编码进策略。**

## 5. 如何运行测试

```bash
python -m pytest tests/
```

264 个测试覆盖：
- 日期对齐、交易日历（`test_dates.py`）；
- 数据 schema 与校验，含**幸存者偏差哨兵**（`test_data.py`）；
- **数据集指纹**（`test_data_manifest.py`）：行序/浮点表示不影响指纹，改动一位小数、
  丢一行、换列类型、改列序都必须被发现，且能指名差异列；
- 因子计算正确性（`test_factors.py`）；
- 股票池 point-in-time（`test_universe.py`）；
- T+1、涨跌停、停牌、佣金/印花税/滑点、组合权重、净值、单边换手（`test_backtest.py`、`test_costs.py`）；
- 绩效指标，含行业暴露与成本归因（`test_metrics.py`）；
- **引擎启动守卫**（`test_engine_guards.py`）：缺涨跌停价必须报错、编程式调用也要跑数据校验、
  暖机期不足必须告警、基准缺 `adj_close` 不得崩；
- **交易权限与数据契约**（`test_constraints.py`）：板块白名单、引擎强制股票池、
  停牌日估值冻结、逐行涨跌停缺失必须报错、`limit_exempt` 豁免、成交量上限、
  目标内缺行情必须留痕；
- **数据装配**（`test_dataset_build.py`）：板块判定、指数剔除、状态/涨跌停合并、
  涨跌停规则表（含创业板改革与 ST 收窄）、六条自检各自能拦住对应坏数据；
- **策略**（`test_strategies.py`/`test_momentum_strategy.py`/`test_low_vol_strategy.py`）：
  散列抽样与 `seed=0` 可复现性、动量 skip 段、防未来函数、低波的流动性过滤、
  容量约束、行业中性选股（含行业只有 1 只时跳过）；
- **基准与超额**（`test_benchmark.py`）：指数代码与个股代码撞车时必须以
  `benchmark.csv` 为准；
- **实盘信号**（`test_live_signal.py`）：整手买入、卖出整手但清仓可带零股、
  小额不下单、停牌持仓冻结且占仓位、样本外持仓清仓、重复跑零订单（幂等）、
  样本按名次补位；
- **增量更新**（`test_incremental.py`）：按 (trade_date, symbol) 精确覆盖、
  窗口内停牌股的旧记录必须保留、重复更新幂等、每日证券数腰斩要报错、
  写盘原子性；
- **成交对账**（`test_reconcile.py`）：四种成交状态（足额/部分/未成交/超量）、
  滑点符号（买贵与卖便宜都记正）、无对应委托的成交单列且费用计入总额、
  超卖与零股卖出告警、持仓偏差按金额排序；
- **公司行动**（`test_corporate_actions.py`）：10 送 10 与现金分红的除权日收益≈0、
  除权后涨跌按复权口径计量、缺 `adj_close` 必须告警、无公司行动时等价于原始价；
- **未来函数专项**（`tests/test_no_lookahead.py`）：
  - 篡改未来数据不得改变历史信号；
  - 成交价必须是 t+1 开盘价而非信号日收盘价；
  - 策略永远看不到 `as_of` 之后的数据；
  - 财务数据在公告日前不可见；
  - 行业分类变更不得污染历史暴露归因；
  - 股票池不受未来状态/未来退市影响。

完整的时间对齐与未来函数审计见 **`reports/lookahead_audit.md`**。

## 6. 如何运行回测

```bash
# (a) 生成合成数据（仅用于框架冒烟测试，非真实市场数据）
python scripts/generate_synthetic_data.py

# (b) 运行等权基准回测（验证数据/股票池/调仓/T+1/成本/净值/绩效整条链路）
python scripts/run_baseline_backtest.py \
    --data-dir data/interim/synthetic --start 2021-01-04 --end 2023-12-29

# (c) 接入真实数据后：把规范文件放入 data/processed/ 再运行
#     需要的文件：bars.csv|parquet, instruments.csv, status.csv|parquet, calendar.csv
```

结果输出到 `results/EXP-<id>/`（净值、成交、持仓、换手、成本、指标、图），
元数据写入 `experiments/EXP-<id>.json`。

每次运行产出的文件：

| 文件 | 内容 |
|---|---|
| `equity_curve.csv` / `equity_curve.png` | 净值曲线与回撤图 |
| `positions.csv` | 每日持仓快照（含权重、可卖份额） |
| `trades.csv` | 逐笔成交，**含被拦截记录**（`blocked:*`） |
| `turnover.csv` / `costs.csv` | 单边换手（`(买入额+卖出额)/2/权益`）与成本（索引为成交日 t+1，非信号日） |
| `annual_returns.csv` / `monthly_returns.csv` | 年度/月度收益分解 |
| `metrics.json` | 全量指标 + 成本归因 + 行业暴露 |
| `cost_contribution.json` | 成本归因明细 |
| `industry_exposure.csv` | 逐日行业暴露权重 |

> 注意：`turnover`/`costs` 的索引是**成交日（t+1）**，不是信号日，做时序对齐时勿错位一格。

## 7. 数据模型（重要）

| 用途 | 使用的价格 | 说明 |
|---|---|---|
| 因子/信号计算 | `adj_close`（后复权） | 避免除权除息造成的假跳空 |
| 成交模拟 | `open/high/low/close`（原始） | 真实可成交价格 |
| 涨跌停约束 | `limit_up/limit_down/pre_close`（原始） | 交易所规则基于原始价 |
| 持仓估值 | 原始价 × 复权因子比 `k_t/k_entry` | `k = adj_close/close`，抵消除权跳空 |
| 财务数据 | 必须带 `announce_date` | t 日信号只能用公告日 <= t 的行 |

数据规范（`src/a_share_quant/data/schema.py`）：
- 行情 long format，一行 = (trade_date, symbol)，必填 OHLCV+amount；
- 证券信息含 `list_date/delist_date`（退市股必须保留，防幸存者偏差）；
- 每日状态表逐交易日覆盖 `is_st/is_suspended`。

**停牌/ST 的权威来源是状态表**。引擎在启动时把 `status.csv` 合并进 bars
（同一 `(trade_date, symbol)` 以 status 为准，bars 的同名列只在缺 status 记录时兜底），
因此成交模拟的停牌拦截不再依赖 bars 的可选列。

**涨跌停必须由数据提供** `limit_up/limit_down`。`consider_limit_up_down: true`
但 bars 缺这两列、或**任意一行**为空值时，引擎**启动即报错**——留空会被当成
"没有涨跌停"而静默放行。不用 `pre_close × 10%` 自行推算，
因为 ST（±5%）、创业板/科创板（±20%）、北交所（±30%）、新股无涨跌幅规则各不相同。
确实没有涨跌幅的（注册制新股上市前 5 日）请用 **`limit_exempt: true`** 显式标注。

**停牌日的行情不参与估值**。数据商在停牌日可能仍给一根理论价 bar，直接拿来
估值会让净值凭空跳变；引擎只接受非停牌日的收盘价。

## 8. 防未来函数机制

- **交易权限**：股票池是"能买什么"的定义，不是给策略的参考意见。引擎在生成
  目标权重后与当日股票池**求交**，池外代码一律不下单，并写入
  `universe_violations.csv` 与 `validation_warnings`——策略即使返回了被剔除的
  ST/科创板/北交所代码，也买不进去；
- **数据校验**：`BacktestEngine.run()` 在启动阶段自行执行 `validate_dataset`，
  **不依赖调用方脚本**——编程式用法（QUICKSTART §6）同样会跑数据校验与
  幸存者偏差哨兵；致命问题直接抛错，非致命告警写入 `result.validation_warnings`；
- **时间对齐**：t 日收盘生成信号，t+1 开盘成交（引擎强制，有测试锁定）；
- **策略视野**：引擎只向策略传 `trade_date <= as_of` 的行情（有测试锁定）；
- **股票池**：`get_universe(as_of)` 只用当时已知信息（上市天数、当时未退市、
  当时状态），未来退市/ST 不影响历史时点；
- **财务数据**：`latest_known(..., date_col="announce_date")` 按公告日取数；
- **因子**：因子只做后视计算（rolling/shift），`compute_as_of` 截断输入；
- **幸存者偏差哨兵**：`check_survivorship_bias` 已接入 `validate_dataset`，
  发现「全表无退市股」或「行情中途消失却未标记退市」时告警（不静默通过）。
  *为什么需要它*：股票池逻辑能在历史时点正确剔除未来退市股，前提是**数据源真的提供了退市股**——
  若数据源只有当前上市股票，回测会被系统性高估，而股票池逻辑本身察觉不到；
- **行业暴露归因**：优先取 `bars.industry` 逐日快照（按 as_of 向后取值），
  退回 `instruments` 静态分类时会在 stdout 显式告警；
  用"最新行业分类"回溯历史会在归因上引入前视偏差。

## 12. 当前已知限制（诚实清单）

1. **没有真实 A 股历史数据**（最重要的限制，见下节）；
2. **公司行动（送转/分红）已在估值层处理**：成交仍用原始价与原始股数，估值按
   `k_t/k_entry`（`k = adj_close/close`）还原，除权日收益≈0。前提是 `adj_close`
   必须是**后复权**序列；若数据源给的是前复权（每次新除权会重写历史因子），
   比值法会失真——`bars` 缺 `adj_close` 时引擎会显式告警；
3. 停牌/退市后持仓冻结在最后已知价（无退市整理期/清算建模）。目标内缺行情的
   标的现在会留下 `blocked:no_bar` 记录，但**不会**被强制清算——终值仍然偏乐观；
4. 调仓日先卖后买仍可能因卖出受阻（跌停/停牌）导致持仓数超过 `max_positions`
   （合成数据里是 21 > 20）。**受阻的卖单不会在次日自动重试**，要等下一个信号日；
5. 买入按"开盘即涨停则不成交"的保守假设，未建模盘中部分成交；
6. 指数成分/市值/行业过滤未启用（缺历史数据，启用时会显式报错而非静默忽略）；
7. 引擎在启动时全量预载行情（内存型），第一阶段规模足够，超大股票池需改分块；
8. 基准对照需要基准指数行情数据，当前数据缺失时不输出对比；
9. 行业暴露目前只有 `instruments` 的**静态**分类可用（合成数据），
   真实数据应提供逐日/逐期行业快照，否则归因存在前视偏差；
10. 因子实现层的"自造未来"（如 `shift(-1)`、跨时间标准化）无法由框架静态阻止，
    必须靠每个新因子配套的篡改测试把关（见第 9 节流程）；
11. **换手率是单边口径**（`(买入额+卖出额)/2/权益`）。旧版本用双边口径，数值约为
    现值两倍，因此 v0.1.0 之后的结果不能与更早的实验直接比较换手与单位成本；
12. 停牌/退市持仓的**市值不计入定仓基数**（否则同一笔钱会被重复分配，导致每次调仓
    现金不足），但这部分资产仍计入总权益，所以持仓权重合计会低于 100%；
13. **绩效指标只统计"策略可能持仓之后"的区间**，建仓前的空仓期（`min_list_days`
    暖机）不计入年化/波动/夏普/超额；`cumulative_return` 仍是全序列（见第 21 条）。
    三个字段各管一件事：`warmup_days` = 被截掉的净值点数、`n_cash_only_days` =
    建仓前的空仓交易日数、`first_active_date` = 首次持仓日。
    早先另有一套 `*_active` 字段，已删除——它算在**已经截断过**的序列上，
    与主口径逐位相同、`n_cash_only_days` 恒为 0，只剩"两套口径"这个混乱来源
    （R05 F-18）；
14. **公司行动缺口已补上**（送转/分红按复权因子还原创除权跳空，合成数据里
    000002 有一笔 2:1 送转做端到端验证）。剩余风险是数据源口径：若 `adj_close`
    是前复权而不是后复权，比值法会失真；这一点只能靠数据侧保证，框架只能告警；
15. `symbol` 是 6 位纯数字，没有交易所后缀，`000001`（深市股票）与上证指数同码。
    板块白名单靠前缀识别，对这类同码只能靠 `excluded_symbols` 兜底，
    长期应改成 `600001.SH` / `000001.SZ` 形式；
16. 印花税用单一税率 0.05%，未按成交日切换（2023-08-28 前实际为 0.1%）；
    过户费未建模。默认区间跨过税率变更点时，早期卖出成本会少算 5 bps；
17. 等权"基准"已改为**散列抽样**（`sha1(symbol)` 排序截断，等价无放回随机抽样，
    可复现），不再按代码字典序。但它仍是**一次抽样的单次结果**（50 只，抽样误差
    约 ±3~4%/年），且不含市值/行业中性化——要当严格基准需要指数成分或市值数据；

    **还要记住它的收益几乎全部来自等权这个权重方案本身**：同一份数据，全宇宙
    等权年化 **9.84%（月频，完整区间）**、中位成交额以上等权只有 0.61%；
    若按回测实际生效的窗口（首次持仓日起，2020-05~2024-12）算，宇宙等权是
    **+4.96%**。所以判断等权策略要先比这一列，**并看清用的是哪个窗口**——
    拿 9.84% 或日频的 8.72% 去比一个从 5 月才开始持仓的回测，会得出错误的超额
    （R05 F-23）。只跟指数比会把等权溢价误读成选股能力。详见第 0 节；
18. **基准指数代码会与个股代码撞车**：`000905` 既是中证500 也是厦门港务，
    `000852` 既是中证1000 也是石化机械。基准必须从 `benchmark.csv` 读，
    不能按"指数代码在 bars 里唯一"的假设去匹配——否则超额、跟踪误差、beta 全错，
    而且不会报错。`_load_benchmark` 已改为优先读文件，并有回归测试锁住；
19. 基准是**价格指数**（不含分红再投资），而组合端的 `adj_close` 估值含分红。
    两者口径差约 1~1.5%/年，这部分会直接算进超额里；
20. 成交量上限（`max_participation_rate`）用的是**成交日全日成交量**，是事后容量代理，
    不是开盘时点真实可成交量。库的默认值是 0（关闭），基线脚本从 `settings.yaml`
    读 0.10；编程式调用请显式传入。`volume` 缺失时引擎会启动报错而不是放行。

    这条限制的**量级**已经实测出来（`scripts/capacity.py` 静态估算 +
    `--capital/--capacity-aum` 实际重跑）：把本金放大并启用容量约束后，
    等权 50 只在 1 亿时年化 7.05%、5 亿 -1.30%、10 亿 -3.23%——
    **容量上限约在 1 亿量级**，再往上组合会被迫漂移成大盘股（5 亿时 -1.30%
    与沪深300 的 -1.11% 几乎重合）。
    不启用约束的 10 亿虽然报 7.46%，但有 16.3% 的成交被成交量上限截断，
    权重与设计不符，**不可解释**。放大资金前必须先解决"开盘可成交量"这个口径
    （需要分钟数据，实测开盘量只有全日的 1/5~1/2）；
21. **绩效统计从首次持仓日开始算（暖机期已剔除）**。回测起点由数据起点决定，
    而 `min_list_days=60` 要求上市满 60 个交易日，所以每段回测开头都有
    **78~79 个交易日空仓**、净值恒为初始资金。这段不计入年化/波动/夏普/超额，
    但保留在 `equity_curve` 与 `cumulative_return` 里；`metrics.json` 的
    `warmup_days` / `n_cash_only_days` / `first_active_date` 分别记录截掉的净值点数、
    建仓前空仓的交易日数、首次持仓日（三者关系：`warmup_days + effective_days = trading_days`）。

    **切点落在首次持仓日的"前一个净值点"，不是首次持仓日当天**：建仓当天的涨跌是
    策略的第一笔盈亏，必须成为 `pct_change` 的第一个值。切在当天会让它从年化里消失，
    而 `cumulative_return` 用的全序列把它算了进去，两个指标自相矛盾。实测三段建仓日
    分别涨 **+2.04% / +1.30% / +1.92%**（都是 5 月第一个交易日，季初建仓），
    年化因此低估 **0.47 / 0.27 / 1.39pp**（R05 F-16）；

    不截的后果实测过：2015-2019 段前 78 天同期中证1000 涨 **69.76%**，
    策略记 0 收益，基准年化从 **-12.48%** 被拉成 **-1.71%**，超额被凭空压低
    70 个百分点。详见 `reports/regression_review_2026-10-21.md` P0 与
    `fix_log.md` 第十六节；
22. **没有任何策略通过实盘门槛**（2026-10-22 第三次修正后仍不通过）。
    等权 50 只三段年化 **+11.15% / -10.33% / +6.11%**，超额
    **+9.59pp（IR 0.925）/ +2.48pp（IR 0.397）/ -4.16pp（IR -0.309）**。
    "样本外大幅失效"**已撤回且超额转正**：2015-2019 基准 -12.48% vs 策略 -10.33%。
    但相对"宇宙等权"这条线（同窗口 -6.02%）只高 4.3pp，接近抽样噪声。
    **"三段里唯一稳定的是动量亏钱"这句话也失效了**：动量 2020-2024 -11.34%
    （超额 -9.26pp）、2015-2019 -4.25%（超额 **+2.63pp**），不再两段同向。
    现在唯一三段同向的是 60 日反转（超额 +7.24/+10.09/+6.92pp，IR 全正），
    但相对宇宙等权只有 +2.4/+2.23/+13.2pp，**还叫不上 alpha**。
    门槛与矩阵见 `reports/live_readiness.md`；这批数字改过三次
    （剔除暖机期 → 切点前移 → R08 F-40 除权卖出结算），
    更早的 9.33/-13.75/3.88 与 9.81/-13.49/5.28 均已作废，
    见 `reports/fix_log.md` 第十五、十六、二十节；
23. **停牌标记在 `status` 表里，不在 `bars` 里**。`bars` 天然只含"有行情"的行，
    它的 `is_suspended` 永远为 False，不能用来判断停牌；引擎以 `status` 为权威来源
    （`_attach_status`）。实测 2015-07-08 有 1,317 只停牌、07-09 有 1,443 只。
    曾把"查了 bars 的列"误读成"数据源不给停牌标记"，见回归审查 P1；
24. **引用参照值必须标明调仓频率**：日频等权与月频等权在 2020-2024 差 1.1pp
    （8.72% vs 9.84%），在 2015 年差 9pp（+27% vs +18%）——日频再平衡会白拿
    再平衡红利，用它当及格线会系统性低估策略；
25. 卖出申报也按整手约束：持有整百股时，卖出数量必须是 100 股整数倍
    （上证函〔2014〕301 号、深证会〔2014〕72 号）。零股仅在清仓时一次性卖出。
26. **暖机截断不区分"股票池为空"与"策略主动空仓"**。前者必须截（否则基准涨、
    策略记 0），后者截了会让超额偏乐观：实测"前 10 天主动空仓、基准 +2%/日"，
    全序列年化超额 -3.71pp，截断后只剩 -2.52pp。当前三段回测的空仓期全部来自
    股票池预热，所以已发布数字不受影响；**写择时策略之前必须先让指标层知道
    股票池哪天有可交易标的**（R05 F-17，暂未修）；
27. **基准序列内部缺日会被记成当天 0 收益**。`benchmark_metrics` 里
    `bench.pct_change().reindex(ret.index).fillna(0.0)`：策略有、基准没有的那天
    填 0，下一天把两天涨跌算成一天。逐日核过三份数据 `benchmark.csv` 与 `bars`
    日期完全一致（缺口 0 天），当前超额未受影响；但 `update_dataset` 每日增量
    会持续制造缺口机会（R05 F-19，暂未修）；
28. **暖机截断有两条路径，在"首次持仓日净值仍等于初始资金"时会分叉**。
    `trim_warmup` 优先用持仓表（首次有持仓的那天），只有拿不到持仓表时才退回
    "净值开头连续平盘"；两条路径对同一段数据可能给出不同切点——实测 9 日合成序列
    前 6 日平盘、第 3 日就持仓：持仓路径 `warmup=1`、平盘路径 `warmup=5`。
    **默认成本模型下不触发**（最低佣金 5 元会在成交日把净值打离初始值），
    三段已发布数字走的是持仓路径、两条路径一致，不受影响。
    触发条件是"零成本 **且** 成交日收盘净值仍等于初始资金"（R06 F-28，暂未修）；
29. **没有持仓表时，`first_active_date` 报的是净值仍等于初始资金的那一天**。
    有持仓表时取首次持仓日；拿不到持仓表时退回 `eq.index[0]`——那是首个收益的
    **基准点**，净值还没动。实测 8 日序列（前 4 日 100 万、后 4 日 102 万）：
    报 `2024-01-05`，而净值真正离开初始值是 `2024-01-08`；`n_cash_only_days`
    按这个提前的日期数，少算了仍处于初始资金的基准日。
    引擎正常产出持仓表时不走这个分支（R06 F-29，暂未修）；
30. **非季度月的"只检查"即使有告警，退出码仍是 0**。`live_signal.py` 在
    `check_only` 分支直接 `return`，不带退出码；于是"已不可投资、清仓"这类
    告警在定时任务里靠退出码看不到，只能看 stdout。依赖退出码的调度必须
    另外解析输出文本（R07，暂未修）；
31. **非季度月现在会执行以前不执行的代码，持仓缺价时会非零退出**。
    R06 F-30 把熔断从"直接 return"改成"照样跑 `build_plan`、只在写文件前停下"，
    于是 `unpriced` 检查与估值 `ValueError` 现在真的会触发。旧代码在这之前
    以 0 退出。新增耗时实测 4–5 ms（`build_plan`），整个进程约 1.7 s（R07，
    行为变化，非缺陷）；
32. **重复入账的指纹保护只防"同一批成交被再对一次"这一种错误**。改单、
    分红送股、对账时漏了一笔、券商回报延迟，它一个都防不住。所以
    **每周至少一次要用券商"持仓查询"导出逐只核对股数**——这是唯一能兜住
    整类问题的检查（R07 §4 条件 5，属于流程要求而非代码限制）；
33. **长回看窗口的策略在短数据段上不可比**。12-1 动量（252 日回看）在
    2025-2026 段（433 个交易日）暖机期吃掉 **64%**（276/433），有效样本只剩
    157 天；另两段是 77%。而这剩下的 7 个月里基准恰好跌 -31.60%，于是算出
    超额 **+22.52pp、IR 1.445**——与另两段的 **-13.44pp / -10.55pp 符号相反**。
    这是**窗口选择的产物，不是动量有效**（动量不可用这条结论由另两段支撑，
    见 `strategy_log.md` §11.1 ③）。
    **评长回看窗口策略时先看 `effective_days / trading_days`**，低于约 70%
    就不该与其他段并列（2026-10-21 重跑时发现）；
34. **除权/分红用「股数不变、按复权价结算」表达，不是真实股数调整**。
    卖出回笼现金 = `股数 × 原始价 × (k/adj_ref)`，与 `position_value` 同口径
    （R08 F-40 修；改前卖出按原始价，10 送 10 的卖出日收益是 **-49.5%**）。
    经济上等价，但两处细节不同：① **整手约束按「虚拟股数」算**——真实世界
    送转后股数变多，可卖的整手数不一样；② `cost` 仍按原始成交额计，
    与复权成交额差 `(1-k/ref) × 费率` 的二阶小量（量级 1e-4）；
