## 二、P0 修复详情

### P0-1 停牌：以 `status.csv` 为权威来源

**改动**：`BacktestEngine._attach_status()` 在启动时把 status 表合并进 bars。

合并规则（关键设计）：
- 同一 `(trade_date, symbol)` 存在 status 记录 → **status 优先**；
- status 缺该记录 → 沿用 bars 的同名列（兜底，避免数据源只提供 bars 标记时倒退）；
- 两者都缺 → `False`。

这样 `ExecutionSimulator` 不需要知道数据从哪来，只读合并后的列即可；
`FakeProvider` 与 `LocalFileProvider` 两条路径行为一致。

**验证**：

```
[PASS] P0-1 停牌（只有 status 表、bars 无该列）被拦截  <- blocked:suspended
```

端到端：合成数据里 SYN0004 在 2022-06-01~07-15 停牌，回测在 2022-07-01
产生一笔 `blocked:suspended` 卖单（此前该场景 0 笔）。

**回归测试**：`test_backtest.py::test_suspension_blocks_trading_from_status_table`
（bars 完全不带该列，必须拦截）、`::test_suspension_falls_back_to_bars_when_status_missing_row`。

### P0-4 现金分配：不再按字典序饿死

三处改动，缺一不可：

**(1) 建仓预留现金缓冲**（`cash_buffer`，默认 1%）
`generate_orders` 用 `equity × (1 - cash_buffer)` 定仓，覆盖佣金/印花税/滑点。

**(2) 现金不足时按比例缩放全部买单**（`ExecutionSimulator.execute`）
先剔除不可买订单（停牌/涨停/无行情），再算总需求；现金不足则
`factor = cash / need` 统一缩放，而不是按顺序整笔丢弃。缩放后按缺口从大到小执行，
避免舍入余量被代码靠前的标的吃掉。

**(3) 定仓基数扣除"当天卖不掉"的持仓市值**（`_sizing_equity`）

这条是审查时发现的**根因**：退市股卖不掉，其市值仍计入总权益，但每次调仓又按
总权益分配目标权重 → 同一笔钱被重复分配 → 每次调仓都现金不足。修复后：
`sizing_equity = 总权益 − 无法交易持仓市值`。

**修复前后对比**（同一份合成数据、780 日、月频）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `blocked:insufficient_cash` | **21 笔** | **0 笔** |
| `blocked` 合计 | 49 | 29（28 `no_bar` + 1 `suspended`） |
| 被丢弃的标的分布 | 集中于 SYN0019/0020/0022（代码靠后） | 无 |

**回归测试**：`test_backtest.py::test_cash_shortfall_scales_buys_instead_of_dropping`
（cash_buffer=0 强制紧现金，断言无整笔丢弃且首日建满 10 只）。

## 五、未修复项（有意保留）

### P1-1 除权除息估值 —— 需要设计决策，不宜仓促改

净值目前用原始 `close` 估值持仓。遇到 10 送 10，`close` 腰斩，持仓市值凭空少一半。
合成数据里 `adj_close ≡ close`，**这条链路无法用现有数据验证**。

三个候选方案，各有代价：

1. **持仓按"复权折算股数"记账**：`shares_adj = shares × k_entry / k_t`，估值用 `adj_close`。
   正确，但要改 `PortfolioState` 的买卖与成本摊薄逻辑，且 T+1 可卖股数、整手下单都要跟着改；
2. **估值层用价格比率还原**：`value = shares × close_t × k_t / k_entry`。
   改动小，但多次加仓时 `k_entry` 需按市值加权，仍有边界情况；
3. **要求数据源直接提供"已处理公司行动的收盘价"**：最省事，但把责任推给数据源，
   与项目"机制优先"的定位不符。

建议先接一小段真实数据（含一次送转），确认 `adj_close` 与 `close` 的实际关系，
再在方案 1/2 之间选。**在修好之前，真实数据回测的净值不可信。**

### 其他保留项

- 涨跌停板块/ST 规则区分：由数据源提供 `limit_up/limit_down` 解决，代码不推算；
- 基准指数必须出现在 `instruments` 才能通过校验（接口设计遗留，暂用文档说明）；
- `data_version` 用文件名+大小+mtime，不是内容哈希（大文件下刻意取舍）。

## 十、D 组：公司行动估值（F-01）

**问题**：净值按原始收盘价估值，10 送 10 当天原始价腰斩、股数不变，市值凭空少一半；
现金分红同理（跌幅≈股息率），且现金没有计入账本。

**方案**：只在**估值层**还原，成交/整手/T+1/涨跌停全部保持原始口径。

```
k_t = adj_close_t / close_t            # 复权因子
持仓市值 = 股数 × 原始价_t × k_t / k_entry
```

- `Position.adj_ref` 记录**建仓当日的 k**；加仓时按市值加权更新：
  `adj_ref' = (old + add) × k / (old × k / adj_ref + add)`；
- 除权日原始价腰斩 ⇒ k 翻倍 ⇒ `k_t / k_entry = 2` 把市值抵回去；
- 现金分红 ⇒ k 按 1/(1-股息率) 上升，等价于股息再投资（总权益不变）；
- 没有公司行动时 k ≡ 1，与旧口径**逐位等价**。

**数据前提**：`adj_close` 必须是**后复权**序列。前复权会在每次新除权后重写历史因子，
比值法失真；`bars` 缺 `adj_close` 时引擎显式告警，不静默按原始价估值。

**顺带修掉一个合成数据缺陷**：原生成器 `close` 取 2 位小数、`adj_close` 取 4 位，
两者 99% 的行不相等，等于给每只股票注入了 ±0.02% 的假除权噪声（基线因此漂移 1.5e-5）。
现在 `adj_close = round(close,2) × 累计送转比例`，k 只取 1.0 或 2.0 两个值。
并给 `000002` 加了一笔 2:1 送转（2022-07-04），让这条链路被端到端走过。

**验证**：

| 场景 | 结果 |
|---|---|
| 10 送 10（原始价腰斩、adj 连续） | 除权日收益 0.000000 |
| 现金分红 5% | 除息日收益 0.000000 |
| 除权后复权口径涨 2% | 收益 = 2% × 持仓权重 |
| 半仓 + 送转 | 除权日收益 0.000000 |
| 无公司行动（adj ≡ close） | 收益 = 原始价涨幅 × 权重，无漂移 |
| 缺 `adj_close` | 告警"除权日收益不可信" |

端到端：`000002` 在 2022-07-04 送转，持仓 1700 股、权重 4.85%（前一交易日 4.85%），
当日收益 -0.24%，与邻日 -0.97% / +0.07% 同量级，无跳变。

新增 `tests/test_corporate_actions.py` 6 项，测试 **109 → 115 passed**。

选股改为 `sha1(symbol)` 排序截断（等价于无放回随机抽样，可复现、跨机器一致），
基准持仓从 20 提到 50（单只 2 万，最低佣金 5 元约 2.5bp，不至于被固定成本吃掉）。

| 累计收益 | +20.33% | **+49.96%** |
| 年化 | 3.93% | **8.80%** |
| 年化波动 | 22.69% | 23.47% |
| Sharpe | 0.283 | **0.477** |
| 最大回撤 | -35.64% | -35.72% |
| 成交 / 被拦 | 957 / 83 | 2160 / 124 |

| 成本占初始资金 | 0.64% | 1.26% |
| 最大持仓数 | 21（配置 20） | 51（配置 50） |

**只改选股方式，年化从 3.93% 变成 8.80%。** 这直接说明第一版数字是噪声——
"最小代码 20 只"恰好抽到了一批 2022-2024 表现差的票。修复后仍是一次随机抽样的
单次结果（抽样误差约 ±3~4%/年），要当严格基准还需要指数成分或市值数据；
但至少它不再系统性偏向任何板块。

**次要观察**：`blocked:insufficient_cash` 117 次（第一版 75 次），
集中在调仓日、表现为末尾几笔买单被压成 0 股；`blocked:limit_*` 各 3 次，
量级正常；`max_positions_held=51` 超出配置 1 只（E 组未修，卖单被拦后不续挂）。

## 十三、基准序列读错了：指数代码与个股代码撞车

**问题**：`_load_benchmark` 优先在 `bars` 里按代码匹配基准，找不到才读
`benchmark.csv`。但 A 股指数代码与个股代码会撞车：

| 代码 | 指数 | 个股 |
|---|---|---|
| 000905 | 中证500 | 厦门港务（深市主板） |
| 000852 | 中证1000 | 石化机械（深市主板） |

两只个股都在主板白名单内、都在 `bars` 里，所以 `--benchmark 000905/000852`
读到的其实是这两只股票的收盘价。000300 恰好没有同名个股，所以沪深300 那组
数字是对的——这种"部分正确"最容易骗人。

**症状**：跟踪误差 35.25%（应该 13% 左右）、beta 0.295（应该 0.8）、
超额只剩 1.87%。用 `equity_curve.csv` 和 `benchmark.csv` 手算对不上，
才定位到这里。

**改法**：`_load_benchmark` 改为**优先读 `benchmark.csv`**，只有当 provider
没有基准文件时才退回 bars 匹配。指数与个股必须分开存，这是数据层的硬约束，
不能靠"代码唯一"的假设。

新增回归测试 `test_benchmark_prefers_file_over_colliding_stock_symbol`：
构造一个 `bars` 里 000852 价格为 10.0 的假行情，断言 `_load_benchmark`
返回 6000.0（基准文件里的指数点位）。

顺带统一了 `benchmark.csv` 的日期格式（部分行带 `00:00:00`，混在一起会
让 `pd.to_datetime` 报错）。

**修正后怎么读这个结果**：超额 +7.4%（vs 中证1000）不是选股能力，但也不是
"市值暴露"这么简单——见下一节的分档分解。

数据质量：六条自检全部通过，无 validation_warnings；
仅 1 行"标了停牌却有成交量"（000670 2022-08-22），属源数据瑕疵。

## 十二、E 组：卖单续挂与退市清算（F-02）

**问题一**：卖单被跌停/停牌/无量拦下后直接丢弃，`pending_weights` 置空，
要等下一个调仓日才有机会再卖。持仓超配会持续一个月。

**改法**：引擎维护 `pending_sells: {symbol: shares}` 队列：
- 卖单没有完全成交（被拦或部分成交）且该标的**已不在新目标里** → 记入队列；
- 之后的每个交易日（不只是信号日）都补挂一次；
- 新信号把该标的重新纳入目标 → 队列里的旧卖单作废，由新目标接管；
- 部分成交时按"剩余持仓"重新入队，不会重复卖。

**踩到的坑**：`Order.reason` 的语义是"本来就下不出去"（例如目标内无行情），
执行层看到非空 reason 会直接记一条 0 股拒绝记录。我一开始给补挂单打了
`reason="retry:sell"` 作为标签，结果所有补挂单都被当成拒绝单跳过——
成交记录里连续几天 `sell 0 retry:sell`，看着像挂了但一笔没成交。标签必须留空。

**问题二**：退市后持仓永远冻结在最后一个价格，终值偏乐观。

**改法**：引擎读 `instruments.delist_date`，过了退市日的持仓按**最后已知收盘价**
强制清算，记一条 `note=forced:delisted` 的卖出记录（成本记 0，因为已无真实流动性）。
这是一个明确的近似：假设能在退市前最后一个可交易价位离场。

**效果**（2020-2024 真实数据，同一份行情）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 持仓超过 50 只的**天数** | 63 | **12** |
| 最多持仓 | 51 | 51（仅当日，次日即卖回） |
| 累计收益 | +49.96% | +52.03% |
| Sharpe | 0.477 | 0.489 |
| `blocked:limit_down` | 3 | 9（补挂导致尝试次数变多） |

剩下的 12 天是"调仓当日超配、次日卖回"的瞬时状态，符合现实。
样本期内没有持仓触发退市清算（策略只持有大盘股），该路径由单测覆盖。

新增 `tests/test_lifecycle.py` 3 项：跌停次日在非信号日补挂成交、退市强平、
旧卖单不与新目标打架。

## 十四、超额到底从哪来：三组等权参照 + 流动性分档

基准修对之后必须回答一个问题：随机抽 50 只，凭什么年化 7~9%，而中证1000
只有 1.0%？为此做了三组**不经过回测引擎**的纯收益参照（同口径：后复权价、
月度调仓、等权、不计成本），以及一次 bootstrap。

### 参照一：随机 50 只 ≈ 全宇宙等权

| 口径 | 年化 | 波动 | Sharpe |
|---|---|---|---|
| 全宇宙等权（3644~4711 只） | **8.72%** | 23.79% | 0.367 |
| 随机 50 只 ×200 次 bootstrap | **8.37%**（σ=2.69pp，5%~95% 分位 4.19%~13.25%） | — | — |
| 策略实测（三个种子） | 6.99% / 7.11% / 7.42% | — | — |

随机 50 只的均值与全宇宙等权只差 0.35pp，**远小于 bootstrap 标准差 2.69pp**。
也就是说：抽 50 只这件事本身不产生收益，它只是把全宇宙等权"复制"了一遍。

策略实测比 8.72% 低约 1.3~1.7pp，差额对应成本（0.26%/年）、现金留存、
整手取整、涨跌停/停牌拦截、以及 T+1 开盘撮合相对信号日收盘的隔夜跳空。

三个种子的持仓**几乎完全不重叠**（交集 0 / 1 / 1 只），年化却只差 0.43pp——
因为每批 50 只都从同一分布抽样，都收敛到那个 8.7% 附近的均值。所以
"换一批股票收益会不会大变"的答案是：单批波动 σ≈2.7pp，但不会系统性偏移。

### 参照二：中位成交额以上等权只有 0.61%

| 口径 | 年化 |
|---|---|
| 全宇宙等权 | 8.72% |
| 中位成交额以上等权（约 1822 只） | **0.61%** |

同一份行情、同样的等权权重，只把"不活跃的那一半"剔掉，年化从 8.72% 掉到
0.61%。**收益全部来自不活跃的那一半。**

### 参照三：按成交额分五档，单调得不像话

每个调仓日按调仓前 60 日均成交额把池子切成 5 档（各约 836 只），档内等权：

| 档位 | 年化 | 波动 | Sharpe |
|---|---|---|---|
| Q1 最不活跃 | **+22.16%** | 23.46% | 0.945 |
| Q2 | +15.76% | 24.04% | 0.656 |
| Q3 | +9.00% | 24.52% | 0.367 |
| Q4 | +2.42% | 25.14% | 0.096 |
| Q5 最活跃 | **-4.62%** | 25.33% | -0.182 |

五档单调递减，从 +22.2% 一路降到 -4.6%，跨度 26.8pp，而各档波动几乎一样
（23.5%~25.3%）。这是教科书式的**流动性/规模溢价**，不是随机噪声。

### 结论

1. **随机 50 只没有选股能力**：它的收益等于全宇宙等权（8.37% vs 8.72%）。
2. **超额 +7.4%（vs 中证1000）来自市值/流动性暴露**，机制不是"中小盘"，而是
   "等权把微盘股的权重放大了几十倍"。中证1000 是市值加权的 1000 只；全宇宙
   等权则是 4700 只每只 1/4700，微盘股权重被极度放大。
3. **这个溢价在纸面上很大，在容量上是陷阱**：Q1 档年化 22%，但这个档位正是
   成交额最低的 800 多只。10 万本金分到 50 只（每只 2000 元）尚可，规模一旦
   上去，`max_participation_rate=0.10` 会先绑死这些标的。
4. 因此**等权"基准"不能当策略**，它的定位应该回到"框架冒烟 + 风格参照"。

### 评估真策略时要带的三条参照

以后任何策略至少要跟这四条比，缺一条都会误判：

| 参照 | 用途 |
|---|---|
| 中证1000（000852） | 市场基准，价格指数（不含分红，约低估 1~1.5pp/年） |
| 全宇宙等权 8.72% | **等权口径参照**——策略打不过它就等于没选股能力 |
| 同流动性档等权 | 控制风格，避免把流动性溢价当成 alpha |
| 随机 50 只 bootstrap 区间 | 判断差异是否超过抽样噪声（σ≈2.7pp） |

这份数据里"全宇宙等权 8.72%"是最关键的一条：任何等权选股策略的收益，
只要在 8.7% 附近，就说明它**只是在复制宇宙平均，没有任何选择**。
