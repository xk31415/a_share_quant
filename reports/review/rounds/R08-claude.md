## 1. F-40（P0）：除权处理只在「持有期间」成立

**这是本轮最严重的一条，因为它污染所有已发布数字。**

引擎的估值口径是 `position_value = 股数 × 原始价 × (k/adj_ref)`，而卖出是
`cash += 股数 × 原始价`（`positions.py:91`）——**两者不一致**。所以：

- 持有期间正确：除权日 k 变了，`k/adj_ref` 把跳空抵掉，权益不变；
- **一卖出就错**：按原始价 × 原始股数结算，送转那部分凭空消失。

本机实测（零成本、6 个交易日、第 3 天除权、之后卖出）：

| 情形 | 权益序列 | 卖出日收益 |
|---|---|---|
| 10 送 10 | 1,000,000 → **505,000** | **-49.50%** |
| 现金分红 5% | 1,000,000 → **950,500** | **-4.95%** |

（505,000 而非 500,000，是因为整手 2000 股的零头现金，方向一致。）

**影响范围我查了**：2020-2024 样本 4711 只股票里，**3983 只（84.5%）在样本期内
至少除权一次**，k 变化行 15,830 个（平均每只 3.4 次）。等权 50 只季度换仓，
几乎每次调仓都会卖出经历过除权的票 → 每次卖出都吃一次假亏损。
**量级是 1~3pp/年，不是小数。**

所以 `9.81% / -13.49% / 5.28%` 这三组数字**必须修完 F-40 后重跑重发**。
在此之前它们偏低，偏低多少取决于持仓期内的送转/分红密度。

**为什么现有测试没抓到**：`tests/test_corporate_actions.py` 六个用例全部是
「买入后一直持有」，断言都在除权日当天，**没有一个用例走到卖出**。
这是典型的「只测了我想到的路径」——和 R07 F-32 是同一类失误。

**修法**：`sell` 的现金结算也走 `k/adj_ref`，与 `position_value` 同口径。
真实世界是「股数变多、价格变低」，我们做「股数不变、按复权价结算」，经济上等价，
且不动整手约束与持仓表。**`adj_ref` 要随 `sell` 一起传进去**。

## 2. F-39（P0）：一条命令毁掉持仓文件，exit 0，无警告

```
跑之前: 600000,1000  000001,500
跑之后: 600000,100          ← 1000 股和 500 股一起没了
exit=0
```

`_load_holdings` 在 `--holdings` 没传时返回 `{}`，然后按空仓算，再把结果
`--save-holdings` 写回去——**原地覆盖**。这一天只要成交全是买入（没有卖出触发
「超卖」的 exit 2 保护），退出码就是 0，标准输出里连「按空仓对账」都不打印
（那行警告只在**路径不存在**时触发，不看「路径存在但没传参数」）。

**为什么这条比 F-36/F-37 更严重**：F-36/F-37 是多记股数，还能靠券商持仓导出发现；
F-39 是**静默销毁一整份持仓**，而且是在正常退出码下发生的。次日建仓会按
「只有 100 股」去算，整批仓位重建。

**修法**：`--save-holdings` 指向的文件已存在、而 `--holdings` 没传时，
**直接拒绝**（退出码非 0），要求显式 `--from-empty` 才按空仓算。
「没传参数」和「真的是空仓」必须区分开——现在的代码把它们当成同一件事。

## 3. F-37（A）：我 R07 加日期双键，反而开了个新口子

```
1st 无 --as-of     exit=0 -> 1100
2nd --as-of 10-21  exit=0 -> 1200
3rd 回到目录名     exit=0 -> 1300
```

**这是我自己造成的。** R06 的指纹只看内容，跨天同内容会被误判，我用「日期+指纹」
修 F-33；结果日期成了可调参数，改一下 `--as-of` 就能绕过。
**修 A 引入 B**——和 F-32 是同一个模式的第二次。

而且注意：**F-36 和 F-37 叠加**才是完整的绕过路径——改导出模板让指纹变，改日期让键变。

**修法方向**：`--as-of` 不该参与「是否重复」的判断，它只该记录「这笔成交属于哪天」。
要防重复，得记**已入账成交的指纹历史**（append-only），不能只比对「上一批」。
这也顺带补掉洞 ①（只记最后一批）。代价是同日内真·两批相同内容会被拦，
用 `--force` 解除——这个口子必须留着，否则误伤比漏拦更糟（R07 已踩过）。

## 4. F-36（A）：指纹 `round(3)` 的精度与券商汇总价对不上

两笔 100 股 @10.01 与 @10.02 → 加权 10.015 → `round(3)` 记 10.015；
券商「交割单」按两位小数写一行 `200 @ 10.02` → 指纹不同 → 1200 变 1400。

本机实测：`200 @ 10.02` 是 exit=0 写到 1400；`200 @ 10.015` 才 exit=1。
**Grok 报的「精确值拦住」也对上了。**

**我认为价格根本不该进指纹。** 指纹的用途是「这批成交是否已被这份持仓吸收过」，
硬信息是 **(symbol, side, shares)** 三元组——股数决定持仓变化，价格不影响股数。
去掉价格后，明细/汇总、两位小数/三位小数、四舍五入方向全部自动吸收。
代价：同日同股数不同价的合法成交会被拦（罕见，`--force` 解除）。

## 5. F-41 / F-42（B）：退市清算的两处实现与注释不符

- **F-41**：`engine.py:313` 记录 `shares: pos.shares`，但上一行 `state.sell` 已经把
  `pos.shares` 减到 0。实测强平行就是 `shares=0, price=10.0`。
  权益是对的（现金按强平前股数入账），**错的是成交记录**——但成交记录是事后核对
  与成本归因的输入，`shares=0` 会让「卖出股数合计」永远少一块。
- **F-42**：注释写「当天又无行情」，但 `310` 行之前只判了 `d < dd`，**没有判当天有没有
  bar**。所以退市日仍有行情时先强平、再按 `pending_weights` 买回来，次日再强平。
  实测：01-04 强平（0 股）→ 当天买 99,000 → 01-05 再强平，持仓一直是 99,000。

Grok 指出 `scripts/generate_synthetic_data.py:73` 的上市区间是 `d <= delist_date`，
**合成数据一定会走到这条路径**——所以用合成数据的实验里，这个 bug 是必现的。

## 6. F-43 / F-44（B）

- **F-43**：`_resolve_as_of` 把非交易日回滚到上一交易日，而季度月判断用的是
  **回滚后**的月份。实测 2023-04-01（季度月）→ 2023-03-31（非季度月）判断翻转，
  2025-11-01 反方向翻转。修法：判断用**请求日**的月份；或者非交易日直接拒绝。
- **F-44**：动量分支 `top_n=pf.get("max_positions", 20)`（配置值 50），而低波分支是
  `top_n=max_pos`（命令行覆盖后的值）。`--max-positions 10` 时动量仍选 50 只，
  再由 `build_target_weights` 按「权重降序、同权重字典序」截到 10 只。动量是**等权**，
  所以截断完全按字典序——**动量名次信息在截断这一步丢光**。
  实测 50 只等权 + 限 10 → 拿到 `000000`~`000009`。

  注意：`397abfb` 的重跑**没传** `--max-positions`，所以昨天那组 -14.90% / -16.09%
  不走这条截断。**但任何传了这个参数的动量回测都不可信。**
