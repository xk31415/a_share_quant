## 三、F-07 ～ F-14 判定

### F-07 目标内缺参考价记成 0 股买单 —— 成立（低-中）

我的探针（周频，1/11 建仓，1/18 目标改为 AAA 1% + BBB 99%，删掉 1/18 的 AAA bar）：

```
2021-01-11  buy   98600  filled
2021-01-18  buy       0  blocked:no_bar
2021-01-25  sell  97700  filled

持仓：1/15 98600 → 1/18 98600 → 1/22 98600 → 1/25 900
```

确认两点：缺口日**没有**生成卖单，持仓从 98,600 维持到下一个信号日；`trades.csv` 把这次
缺口记成 `buy`。你原报告的结论成立。

严重度我定为**低-中**：当天没有 bar，本来就无法成交，实际损失只是"减仓推迟一个信号周期"；
真正的伤害在审计——事后看 `trades.csv` 会以为策略当时想加仓。

处置：`generate_orders` 在参考价缺失时，已持仓记 `sell`、未持仓记 `buy`，方向与真实意图一致。

### F-08 `volume` 为 NaN 时上限静默关闭 —— 成立（高）

```
volume 全 NaN，max_participation_rate=0.10
成交: 2021-01-05 buy 99,000 filled capped=False
```

同意"高"：`volume` 是必填列，NaN 属数据异常，而 `validate_bars` 只给 warning，
容量约束就这样无声消失了。处置：`max_participation_rate > 0` 时，`volume` 出现 NaN 在启动阶段
直接报错；执行层再加一道 `blocked:no_volume_data` 兜底。

### F-09 卖出上限不按整手取整 —— **不成立**

事实部分我复现一致：`volume=2500`、rate 0.10 → 卖出 250 股、剩余 750。

但结论不成立。A 股交易规则里，**只有买入**要求"100 股或其整数倍"；卖出不要求整数倍，
仅对"余额不足 100 股的部分"要求一次性申报。250 股是合法申报数量，不会出现你说的
"交易所委托规则不允许的股数"。

买卖两侧取整口径不一致属实，但属**风格问题**，不列为缺陷。

> 如果你有交易所规则原文能推翻这条，请贴出来，我改判。

### F-10 开盘撮合用全日成交量 —— **条件成立**

事实确认，两个世界只改 `volume`：

```
volume=       1,000 -> 首笔买入   100 股，开盘价 10.0
volume=  10,000,000 -> 首笔买入 99,000 股，开盘价 10.0
```

但这是**有意的建模选择**：开盘时点拿不到全日成交量，用全日量做事后容量筛查是通行做法。
按你写的撤回条件——"若定义就是事后容量筛选，则本条不成立"——我判定为**条件成立**：
作为缺陷不成立，作为"文档缺失"成立。

处置：不改代码，在 README 与 `settings.yaml` 注释里写明"该上限用成交日**全日**成交量，
是事后容量代理，不是开盘时点可成交量"。如果你认为这个定义本身不可接受，请给出替代口径，
我们再议。

### F-11 流动性均值分母是有 bar 的行数 —— 成立（中）

```
lookback=5，阈值 200
FULL 每天 amount=100 -> 不入池（正确）
GAP  仅最后一天 amount=600 -> 入池（应为 120，不该入池）
宇宙 = ['GAP']
```

同意：单日放量可以顶过按交易日数平均的阈值。处置：分母改为窗口内交易日数
（`sum(amount) / n_trading_days`），缺 bar 的日子按 0 计入。

### F-12 parquet 整型 symbol 前导零丢失 —— 成立（中）

```
parquet symbol=1 -> bars ['1']，instruments ['1']
白名单 ['000','600'] 下宇宙 = []
```

确认只在 CSV 分支传了 `dtype`。处置：parquet 分支读取后校验 `symbol` 必须是字符串类型，
否则启动报错——前导零一旦写进整型就**无法还原**，只能要求数据源修正，不能替它猜。

### F-13 现金缩放被记成 capped —— 成立（低）

```
现金 5,000，委托买入 2,000 股，volume=1,000,000，rate=0.10（上限 100,000 股）
成交 400 股，note=filled，capped=True
```

同意。处置：`capped` 只在"成交量上限实际绑定了股数"时为真，即 `want > cap`；
由现金或整手造成的缩量不计入。

### F-14 全样本警告不落盘 —— 成立（低）

```
全样本（含第 1 天 volume=NaN）: 有 volume 告警
窗口（第 4 天起）:             无 volume 告警
```

确认脚本只把 `result.validation_warnings` 写进产物，全样本那份仅打印。处置：落盘改成
`all_warnings`，同时保留来源标记（`source: full_sample | backtest_window`）。
