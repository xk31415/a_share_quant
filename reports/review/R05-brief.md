## 3. 本轮审什么（按优先级，五个）

范围：`b09dadc..7b6b5ef`，66 个文件、+11,387 行，以及它们影响到的旧代码。

### P1（最高）`metrics/performance.py` 新增的 `trim_warmup`

这是**唯一一个会改写所有已发布数字**的改动：它把每段回测开头 78~79 个交易日的空仓
踢出年化/波动/夏普/超额，理由是 `min_list_days=60` 让股票池为空、净值恒为初始资金，
而基准同期是活的（2015-01-05~05-04 中证1000 涨 69.76%）。

要查的不是"它有没有用"，而是**它会不会误伤**。至少尝试这几个反例，成功失败都写：

1. **首日建仓但当日无成交**（T+1，持仓次日才落地）：会不会把真实的第一天当暖机截掉？
2. **全程空仓的择时策略**：`n_flat == len(eq)` 时是否真的不截（否则指标全 NaN）；
3. **中间空仓**：只有开头平坦、中途又空仓几个月，截断是否只动开头；
4. **`positions` 里 shares 全为 0 但日期有值**：会不会截到末尾导致序列过短；
5. **`cumulative_return` 用全序列、`annualized_return` 用截断序列**——这个不一致
   是否在 README 第 21 条与 `fix_log.md` 15.1 里说清楚了？如果没写清，
   读者会把"累计收益"和"年化"混着引用，那是一条文档缺陷。

### P2 报告与 README 里的数字是否出自同一实验、同一口径

里找到对应键；③ 有没有引用"完整区间"的参照值去比"截断后"的回测（窗口没对齐）。
